# 拾途杭州公开版浏览器验收

2026-11-11 · Chromium 独立浏览器会话 · GitHub Pages / Render

[公开演示](https://yuchangceng065-hub.github.io/tripcanvas-demo/) · [54 秒操作录屏](https://github.com/yuchangceng065-hub/tripcanvas-shitu/releases/download/demo-2026-11-11/tripcanvas-demo.webm)

录屏展示云端连接、测试注册、Agent 反问、补充需求、确认保存和重新登录。录制使用临时账号和测试行程。

| 场景 | 验证方式 | 结果 |
| --- | --- | --- |
| 首次连接慢 | 浏览器将首个 health 请求替换为 503，后续请求连线上 API | 显示唤醒提示，随后恢复为「云端已连接」 |
| 注册与 AI 规划 | 从公开页注册，进入新旅行，补充人数、交通方式并确认 | 注册 200，收到 Agent 方案，确认接口返回 200 |
| 事件流断开 | 浏览器主动中断第一次事件请求 | 客户端再次发起事件请求，同一任务继续 |
| 刷新后继续未确认任务 | Agent 在反问时刷新页面，重开新旅行并点「继续刚才的 AI 任务」 | 读回同一运行并显示原对话和补充入口 |
| 重复确认 | 双击「确认并保存 Agent 方案」 | 浏览器发出一次确认请求，PostgreSQL 只保留一个行程版本 |
| 已保存行程刷新可见 | 保存后刷新，进入「我的旅行」 | 测试行程仍可打开 |
| 会话失效 | 在服务端撤销当前测试会话，刷新后重新登录 | 失效会话被拒绝，重新登录能找回已保存行程 |
| 高德底图失败 | 阻断高德 SDK，路线请求继续访问后端 | OpenStreetMap 底图渲染，时间轴仍显示高德转场用时。回退底图省略高德坐标系的路线和地点 |

冷启动和网络故障使用浏览器侧故障注入。断线后的事件游标完整性另由 [Agent 任务评测](evaluation.md#脱敏真实任务与版本对比) 检查。一次刷新后的回归出现额外反问，已在界面核实对话仍保留，完整确认保存则在另一试次跑通。
