# 自由需求、多轮澄清与原任务续接

范围仍为杭州 1—3 日步行或自驾接驳。自由文本先被整理为结构化事实；地点必须来自真实搜索并由用户明确选择；需求确认后才执行道路规划，最终再确认保存。

## API

- `POST /planner/conversations`：text、title；返回 runId，后台理解需求并搜索地点。
- `GET /planner/conversations`：仅当前账号最近五个待继续任务，不返回内部上下文。
- `GET /runs/{id}`：运行结果与 conversation 视图，包含版本、对话、待补条件、真实地点选项、已选项与确认状态。
- `POST /planner/conversations/{id}/reply`：version、requestId、text、choices、confirm、retry。普通回复、地点选择、确认需求、失败重试分别提交。同一编号重复请求幂等，不同内容复用编号或旧版本返回 409。

choices 只能从本任务搜索结果中选择；confirm 只能单独用于完整的 review 状态。缺条件、地点未确认、城市/天数不支持、返程不完整、重复地点或时间矛盾时均不能确认。

## 状态与预算

`running → needs_input → running → needs_confirmation → running → completed`，其中可再次进入 needs_input。所有激活使用同一个 runId 和递增事件序号。

- 初始语义理解及修复最多 8 次模型请求；每任务最多接受 6 次补充/确认/重试。
- 路线 Agent 每次激活最多 6 步，跨反问累计最多 12 步，重试与重启不重置预算；每次处理最多 240 秒。
- 地点搜索累计最多 12 次，缓存已返回候选，纯选择地点不再次调用模型。
- 新建任务扣每日 Agent 额度；继续同一任务不重复扣新建额度，但仍受补充/调用预算和限流约束。
- 进程中断后标记 interrupted；检查点保存在数据库，可由用户继续原任务。外部只读查询可能重新核验，不承诺无重放的分布式执行。

## 语义与约束

模型提取完整事实快照；规则复核明确日期、人数、交通与返程，保留前文未被撤销的事实。特别处理“人数还没定”“走路还是开车”和明确取消返程，避免猜测或保留已撤销条件。返程时刻不会被当作普通结束时间。模型首次真实验收曾遗漏返程点，已据此增加规则与回归，保留失败事实。

软偏好作为规划上下文，不能解除已确认的必去、候选、时间与返程硬约束。要改变已确认硬条件，应返回重新确认需求；当前自由回复仅补充偏好，不自动扩大授权。营业、台阶、票价、预约、景区内步行等未核验信息仍显示待核对。

## 搜索词规划与跨任务偏好

- 语义提取阶段模型可为每个地点提及给出 0—2 个补充搜索词（多校区、同名、区域歧义），服务端按“模型搜索词 → 原始提及”顺序搜索、合并去重，单任务搜索上限 12 次；用户仍需按地址确认，不自动选第一个。
- 每个搜索词写 `place_search` 事件（含 query 与次数）。当前是一次性查询规划，不是“看结果再追问”的多轮搜索；用户点选仍由现有选择卡片完成。
- 确认保存后，仅把 pace / interests / walkBudgetKm 写入 `user_preferences`；新建对话时注入模型上下文并补全缺失的软字段，用户明说的值优先。`GET/PUT/DELETE /api/v1/preferences` 可查看、修改、删除；不保存原始对话、硬约束或思维链。

## 数据与恢复

新增 planning_sessions 与 Alembic 增量迁移，按账号归属隔离。存储用户明确输入的对话、结构化事实、地点选择和模型动作执行上下文；不存模型思维链或密钥。运行事件不记录全文对话。API 仅返回公共视图，不返回系统提示词和内部 checkpoint。账号切换清除本地待继续编号；登录后可从云端最近任务恢复。

检查点保存消息、工具观察、已消耗步骤和累计 usage。原 Agent 的 need_input 现在也支持回复续接；后续请求不会重建旅行或生成新的 run。所有结果依然经过程序道路核验和最终确认事务。

## 验证

新增后端回归覆盖自由描述→补充→选点→确认→规划反问→同编号完成，幂等/旧版本/越权/伪造候选、模型失败重试、累计预算、重启检查点与跨轮事实遗漏。前端覆盖 Enter 回答、地点确认、未确认不保存、网络重发相同幂等号、旧编号恢复。真实模型、地图和浏览器验收分别记录，固定工程评测不当作模型准确率。
