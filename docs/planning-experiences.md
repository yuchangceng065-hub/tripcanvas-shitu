# 行程推演、修复解释、攻略导入与执行回放

## 入口与实际行为

- 画布顶部「行程推演」：先同步当前计划，调整单日出发时间或全程每日步行上限。停止拖动 900ms 后请求核验；本地即时预演明确标为未核验，旧请求不能覆盖新条件。
- 推演保留必去、固定预约、返程和每日结束条件。修复可勾选保护选定出发、停留与全部地点；核验原顺序、未锁定停留下限、可选地点取舍和相邻换序，组合最多 8 个候选、65 秒。复用整日路线，保持自驾车辆连续性。排序依据可行性、剩余错误数和改动条目数，不宣称全局最优或最小冲突集。
- 冲突与修复逐项展示实际道路核验、变更、指标、仍存在的问题。仅可行结果允许保存为分支；失败保留原计划。
- 分支库：每份原计划最多 20 个不可变分支，绑定来源旅行与版本，保存幂等、防并发覆盖；可删除、重新打开、并排比较。打开为独立旅行，初次打开再核验道路；重复打开返回已打开旅行的当前版本。删除分支不删除已经独立打开的旅行。
- 新建向导「选择地点 → 从收藏的攻略批量导入地点」：最多 6,000 字、8 个提及；AI 名称与连续引用必须逐字存在于原文，保留位置供高亮。原文不作为指令执行；推荐/可选/否定分别处理，否定不搜索。真实搜索每提及最多 3 个候选，用户逐项选地址、合并真实 ID，再批量加入；既有必去不会自动变为可选。攻略日期不成为出行日期。最近五次导入可跨会话恢复，原文只对当前账号可读。
- 画布顶部「规划回放」或推演结果的回放按钮：选择本人最近运行，播放/暂停、单步、进度拖动；详情来自事件摘要、真实时间戳与累计模型用量。播放不执行模型、不重新保存、不展示隐藏推理。相邻事件间隔包含处理/等待，不能当作精确单工具耗时；旧事件没有时间则不编造。

## API 与数据

`POST /planner/simulate`；`GET/POST /branches`；`POST /branches/{id}/preview`；`POST /branches/{id}/open`；`DELETE /branches/{id}`；`POST /planner/import-guide`；`GET /planner/imports`；`GET /runs`。均要求登录并按 owner 隔离，外部查询受原有地图预算限制。

新增 scenario_branches 与增量 Alembic 迁移。分支记录来源、标签、幂等号及内容摘要、完整服务端地点快照，保存前重算道路，外部 I/O 后再次检查来源版本。分支与原计划独立，不能借分支接口解除锁定或返程。删除来源旅行会清理其分支记录。

推演每用户 6 次/分钟、30 次/日；攻略 2 次/分钟、6 次/日。攻略失败不自动改用付费模型。

## 验证

前端 100 项、后端 163 项，新增覆盖条件改变后旧核验失效、未确认不写入、原文出处/否定/同 ID 合并、回放不重复执行、固定返程保护、修复开关、分支幂等/过期/越权/独立打开、导入历史按账号隔离。

本地浏览器使用隔离 SQLite、真实 OSRM，攻略语义使用脚本模型：09:30 改 13:00，原顺序 18:09 到站，比固定 17:00 晚 69 分钟；可选博物馆舍弃后核验可行，分支保存、刷新、重新比较、独立打开均通过。原计划保持 09:30。攻略两处确认加入，一处否定未加入；回放单步与读取详情通过。390×844 的页面与弹窗无横向溢出，所检页面无 error 日志。真实 Groq/高德线上结果另行记录，不把脚本模型当真实 AI。

## 边界

仍为杭州 1—3 日步行/自驾接驳；没有新增动态旅程预演。地图、营业、票务、停车可进入性及景区内通行的既有边界保持。当前分支是独立快照，不做自动合并；比较突出地点、停留、分日和指标，不承诺道路查询时刻一致。未核验或仍冲突的推演可查看，不能保存为有效分支。
