# 高德分段交通接入

## 本次范围

- 地图切换到高德 JS API 2.0，地图、地点与路线使用 GCJ-02。既有 OSM/WGS84 地点通过高德官方坐标转换接口进入高德算路，原始坐标保留。
- `walk` 使用高德步行；`drive` 表示自驾＋步行接驳。后端按“步行回停车点 → 取车预留 → 驾车 → 停车预留 → 步行到景点”生成分段并累加距离与时间。
- 当连续景点使用同一停车点时直接步行，车辆留在原处；下一次开车前返回该停车点。
- 默认在附近最多 20 个候选中推荐停车点，并明确标为待确认。名称或地址中明显包含内部、专用、职工或大学停车场的候选，不自动选用；用户手动选择时提示确认通行资格。这是保守的文本规则，不是停车场开放性的保证。用户可以在“交通与停车”中选择、确认，修改后先预览，确认才应用和同步，支持历史恢复。
- 车辆初始位置按**当天首站所选停车点**计算。车位、停车费用、开放与内部入口权限不做保证。不是实时导航，也不预测未来出行日的交通。
- 公交地铁、打车、多交通方案比较留待后续，本版没有假装实现。

## 服务端配置

Render 环境变量：`AMAP_WEB_KEY`、`AMAP_JS_KEY`、`AMAP_JS_SECURITY_CODE`。三项齐备且 `ROUTING_PROVIDER` 不为 `osrm` 时启用高德。JS Key 应限定到本站域名。`PUBLIC_API_ORIGIN` 为服务端 HTTPS 地址。

JS 安全密钥使用服务器代理，公开配置只包含域名限制的 JS Key；Web Key、安全密钥均不返回浏览器。代理只允许地图样式资源路径和本站 Origin，并校验 JS Key，不提供任意上游转发。真实 AI 继续遵循 `PLANNER_MODE=rules`，高德接入不会启动付费模型。

## 请求预算与缓存

`provider_usage` 表保存每日、每月计数。每个真实 REST 请求前以数据库事务预留计数；达到预算返回 429，不重置计数、不切换供应商。默认本站预算：基础 LBS 10000/月、500/天；地点搜索 1000/月、100/天。它们是本站控制值，不能替代高德账户实际配额监控。

高德 API 的 HTTP 200 还会检查 `status/infocode`；密钥错误、额度限制、无路线均明确失败，不生成虚假路径。请求串行限速，队列与缓存有上限。驾车段最多复用 5 分钟，步行段最多 24 小时；完整路线到期时间受最早过期的分段限制。缓存身份包括供应商、地点坐标、停车点和预留时间，避免复用旧单一驾车结果。

## 验证

- 真实接口初测：曲院风荷 → 孤山馆区，步行 126 米＋驾车 1.958 公里＋步行 195 米，含 5 分钟手动预留为 20 分钟；该数值仅为测试查询时结果。
- 前端覆盖分段总时间、路线结构与坐标系校验、停车条件导致缓存失效；后端覆盖真实响应解析、共享停车点车辆连续性、配额拒绝与计数持久性、官方坐标转换、密钥不外泄及代理限制。
- 发布后另行执行真实网页验收，检查地图、添加地点、停车确认预览及云端保存。
